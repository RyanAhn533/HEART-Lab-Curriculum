# 3-7. 특성이 너무 많으면 — PCA (Principal Component Analysis)

> **Ref: Stanford CS229 W6 / 정규과정 5/22 PCA 슬라이드 / AI5 ml/m01~05**

---

## 왜 배우는가

데이터 특성이 30개, 100개, 1000개일 때:
- 학습이 느리다
- 시각화가 불가능하다 (3D까지만 그릴 수 있음)
- 불필요한 특성이 성능을 떨어뜨린다

PCA는 **중요한 정보를 최대한 보존하면서 차원을 줄이는** 방법.

---

## 1. PCA란?

**"데이터의 분산이 가장 큰 방향을 찾아서, 그 방향으로 축을 정렬"**

```
원래 특성이 10개 → PCA로 3개로 줄임
  → 정보의 95%를 3개 축으로 표현 가능
  → 나머지 7개는 노이즈에 가까움
```

---

## 2. 설명된 분산 비율 (Explained Variance Ratio)

```
PC1: 72%  ← 가장 중요한 축
PC2: 18%  ← 두 번째
PC3:  5%
PC4:  3%
PC5:  2%
합계: 100%

→ PC1~PC2만으로 90% 설명 가능
→ 10차원 → 2차원으로 줄여도 정보 대부분 유지
```

---

## 3. 언제 PCA를 쓰나?

| 상황 | PCA |
|------|-----|
| 특성이 매우 많을 때 (100+) | 차원 축소 |
| 시각화하고 싶을 때 | 2D/3D로 축소 후 scatter |
| 모델 학습이 너무 느릴 때 | 특성 수 줄이기 |
| 다중공선성이 있을 때 | 상관 높은 특성 합치기 |

---

## 4. PCA 주의사항

- **스케일링 필수** — PCA는 분산 기반이라 범위가 다르면 왜곡
- 변환 후 특성이 **해석 불가** — "PC1이 뭔지"는 설명 어려움
- 비선형 관계는 못 잡음 → t-SNE, UMAP 등 대안
